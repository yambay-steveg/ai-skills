A field guide to the session-card system

Work is a card.
Memory is a folder.

A personal, plain-text way to run long work across many short AI coding sessions — without losing the thread. Everything is markdown you can read, tracked by one small tool. Here is the whole model on one page.

Context A folder
The working files on disk. This is the memory — state lives here, not in any one chat.
+
Session A working stint
One Claude Code sitting. Start, stop, resume — as many as the job needs.
→
Card The handle
A markdown note binding a context + its sessions + a status. One card, many sessions.

Four layers, one of them does the work

Everything hangs off a shallow hierarchy. The card sits in the middle — it is the project, so there is no separate project layer to maintain. Only cards appear on the board; the layers above are ordinary vault notes.

Area
A standing domain of work — area/work-ops, area/v7. Broadest bucket.
vault note · a folder + folder-note
│
Program
A named body of related work a card calls home, e.g. [[managing-ai-activities]].
vault note · linked from a card
│
Card = Project
The trackable unit. A deliverable effort binding a context folder, its sessions, and a status.
markdown card · the only thing on the board
│
Session
A working slice of one card — a subtask, a new day, a context reset. Logged, never its own card.
a transcript · listed under ## Sessions

Hierarchy runs through wikilinks (a card's program:). Everything else is a facet tag.

Anatomy of a card

A card is just a markdown file with frontmatter — legible on its own, and the single source of truth for status. Every field earns its place.

work-knowledge/Cards/session-card-board.md 
---
type: project
title: Session Card Board
status: in-progress
summary: A local web cockpit over the cards
program: "[[managing-ai-activities]]"
raised-at: "[[e-and-a]]"
tags: [area/work-ops, kind/tooling]
sessionId: 9ff88f23-8e91-…
paths:
  - …/claude-code-steveg/active/session-card-board
  - …/yambay-steveg/session-card-board
---

## Sessions
- `9ff88f23` — 1 Jul — built the archive lifecycle (current)
- `4e7bd75c` — 30 Jun — reconciled the board card
status
The lifecycle state — the source of truth. Drives the board and, on the disk, where the folder lives.
program: [[…]]
The card's home in the hierarchy. A wikilink, so it survives renames and can be a list for multi-membership.
raised-at: [[…]]
Provenance, kept separate from home: where this came up (a meeting/forum). A card can live in one program yet trace to another place.
tags: area/… kind/…
Facets, not hierarchy. Multi-valued and shared with the rest of the vault's notes.
paths:
The context folders this card works on — the memory. First one is the primary (where sessions run).
sessionId · ## Sessions
sessionId is just the current pin to resume; ## Sessions is the readable history — one card, many sessions.

Where everything is stored

Three homes, each holding what it's best at. The card lives in the knowledge vault; the work lives in the task repos; the sessions live where Claude keeps its transcripts. The card's fields are the wiring between them.

Tags describe, links connect

Two different jobs, kept deliberately apart. Facets are flat labels you filter by; edges are wikilinks that place a card in the graph.

Facets — tags

Flat, multi-valued labels. A card can carry several. Shared with every other note in the vault.

area/work-ops area/v7 kind/tooling kind/decision jira/PRODEV-23590

Edges — wikilinks

Whole-value links, so a rename updates everywhere. Each edge means something distinct.

program: Home. The program this card belongs to.
raised-at: Provenance. The forum/meeting it came from.
customer: Stakeholder. A cross-cutting party the work is for.
Their targets — Programs, Forums, Customers — are all vault notes (a folder + a same-name note), never cards. The link feeds their backlinks as a zero-maintenance index.

The lifecycle

status is the source of truth; the disk is reconciled from it. Move a card through these and the folders follow.

backlog
Captured, not started. On the board.
in-progress
Being worked. The live column.
on-hold
Paused, still on the board.
done
Finished. Off the board; folder kept in place.
archived
Filed. Folder moved to archive/; inert until reinstated.

Three rules that hold it together

01
Folder is memory, session is a stint, card is the handle. Break work into as many sessions as you like — the folder carries the state, so any session can pick it back up.
02
One tool writes the cards. cardctl is the single validated writer — the board and the sessions change cards through it, never by hand-editing frontmatter. Renames go through Obsidian so links never break.
03
Working memory, not the record. When work finishes, the durable knowledge graduates out to its real home — the vault, the repo, Jira, email. The card system holds the thread while it's live.
→
How you actually drive it: a Kanban board (an Obsidian base, or the web cockpit). Pick a card, hit launch — the right folders open in your editor and the matching session resumes.
